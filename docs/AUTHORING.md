# Authoring lessons — the API

How to write a lesson, a beat and a picture. The rules of *what* to write
are in [PEDAGOGY.md](PEDAGOGY.md); this is *how*, as built. Written by the
two foundation workstreams (F1: the beat engine and the bubble; F2: the
stage pictures) and kept in step with the code.

## The beat engine (content/lessons/core.ts)

IMPORTS. Lesson files import from './core' (not './index', which imports them, so that would be a cycle). Everyone else imports '../../content/lessons' (index.ts re-exports all of core plus LESSONS). Register a new lesson in content/lessons/index.ts (import it, add `[x.id]: x` to LESSONS, re-export it). The helpers core exports: heard, was, worked, ever, points, sameObject, targetOf, errorType, stopped, bareWord, commaDecimal, boolMiss, countMiss(line, things), measureMiss, wordsMiss(line, example), cap, digits. numberOf, boolOf and textOf still come from '../../src/scene/props'. The speaker names are in content/cast.ts: CROW_NAME = 'Corvid', and SPEAKERS = { crow: {name: CROW_NAME, colour:'--ink'}, robot: {name:'Robot', colour:'--brand-deep'}, courier: {name:'Mira', colour:'--mira'} }. Write '{CROW_NAME}' inside any line and script() fills in the name.

TYPES (core.ts):
type CastAction = { actor: string; do: 'enter'|'hide'|'wave'|'hop'|'sleep'|'wake' }
type Focus = 'console'|'memory'|'run'
type Beat = { say: string; speaker?: string /*actor id, crow if omitted*/; show?: Prop; thought?: string; act?: CastAction[]; focus?: Focus }
type LessonStep = { say: string /*THE ASK only (R3)*/; speaker?: string; done: (e: Evidence)=>boolean; show?: Prop; ask?: string; nudge?: (l: Line)=>string|undefined; beats?: Beat[]; praise?: string | ((answer: Heard|null)=>string); tag?: 'you'|'robot' }
type Lesson = { id; teaches: string[]; steps: LessonStep[]; outro: string | Beat[]; outroSpeaker?: string; ordered?: boolean; finale?: Prop; takeaway?: string }
type ScriptItem = { kind: 'praise'|'beat'|'ask'|'reply'|'outro'; asking: boolean; text; speaker?; show?; thought?; act?; focus?; tag?; beat?: number }
type Script = { at: number; before: number; finished: boolean; items: ScriptItem[]; rest: number }

script(lesson, evidence) is pure and derived. For step `at`, items are: [praise of step at-1, if that step has one] + one item per beat of step at + the ask. The ask becomes kind 'reply' (the nudge's text) while a miss applies, in the same position. A miss is a line that did not move the lesson: `beforeLast(evidence)` takes the last line back out (its thought, and its memory entry, which the workbench hands over as `Line.memory`), so a binding that did a step (`x = 10`) is never answered as a miss to the step after it. Once finished, items are [praise of the last step, if it has one] + the outro (a string outro counts as one beat). `rest` is the last index: the ask, or the final outro line. The praise stays in the list for as long as the player is on step at, so the list never shifts under the index. A praise function receives the thought that did the step (exact in an ordered lesson). Praise is always spoken by the crow. guidance(lesson, e) = { text, speaker } of items[rest], as before. A lesson with no beats, no praise and a string outro has exactly one item and behaves as it did before this change.

staging(lesson, e, beat?) (beat is an index into items; defaults to rest). While a beat shows, the picture is the latest `show` at or before that beat, falling back to the step's `show`, or to `finale` once finished. A beat picture's key is `${id}:${at}:b${i}` only when it differs from the step's picture, so a picture shared across beats stays the same element. The ask brings the step picture back under key `${id}:${at}`, with its `ask` text under it, and a miss is drawn in only on the ask or reply. During praise the answered picture stays on screen (key `${id}:${at-1}`, verdict 'right', answer drawn in, no question under it). After a praise, nothing plays a 'leaving' animation; without a praise, leaving works as before.

castAt(lesson, e, beat?) → { hidden, asleep, acting }. An actor whose first action anywhere in the lesson is 'enter' stays off stage until that beat (e.g. Mira in the types and choose scenes: the courier actor is always in the scene spec). 'hide' sends an actor off again. sleep/wake persist (the robot's screen goes dark or lights up). wave/hop play only while their beat is showing. Everything is folded from all beats of earlier steps plus the current items up to the index, so Back and resuming a level both give the right cast.

HOW IT RENDERS. Beats, praise and outro items are narration: the console is disabled with the placeholder 'Listening… press Next'. A big Next button sits bottom-centre with a small ◂ Back beside it. Enter or Space anywhere advances; the first press finishes the typing and the second moves on. A thin bar of steps runs along the top of the stage. At the ask or a reply the console is enabled, focused and glowing; Next is hidden; a 'Type your answer →' pointer appears bottom-right (not in editor mode); once the panels stack (≤ 1000px) its arrow turns down, to the console below. Everything on the stage's bottom edge (Next, the pointer, the takeaway, Continue) is lifted above the scene's hint strip when it shows. The bubble's name pill shows the speaker's colour; the tag appears as a 'You answer' or 'Robot works it out' pill on the ask; a reply has a soft amber tint, never red. Text types on at about 45 chars/s, pausing at , ; : . ! ?, with `code` chips appearing whole. A beat's `thought` shows in the robot's cloud during that beat only (`''` empties it); it is never evidence. Otherwise the cloud shows the robot's newest real thought only while it belongs to what is being told (`cloud` in core.ts): one thought since this step began, or the answer while its praise is read. On the next item after a praise it clears, so an old answer never stands over the next question. `focus` pulses the console, the memory pane or the Run button. Once finished and resting on the last outro line, the takeaway bar shows with Replay (which jumps back to the first outro beat), and the console opens again. Continue (.advance) still shows as soon as the lesson is finished (invariant 10). Keep each beat or praise line to 110 characters or fewer: tests/unit/lessons/every.test.ts enforces this for every lesson.

WRITING A UNIT TEST: put it in tests/unit/lessons/<id>.test.ts and import { line, failed, typed, th, over, snap, bound, value, NOTHING, EMPTY } from './fixtures'. Examples: progress(lesson, typed(line('True', th('bool','True')))); script(lesson, typed(failed('seven','NameError'))).items[s.rest].kind === 'reply'; staging(lesson, NOTHING, 1).current.key; castAt(lesson, NOTHING, 0).hidden. Every registered lesson is also checked automatically by every.test.ts, and every.test.ts also checks that every lesson named by an activity is registered, and vice versa.

WRITING A BROWSER JOURNEY: put it in tests/browser/lesson-<id>.spec.ts and import { open, say, skip, beat, send, reprs, targetOf, seedProgress, WARM_UP, OPS, speechSettled, EDITOR } from './helpers'. say(page, line) skips narration first, then types into the console and waits until the robot is no longer busy. beat(page) returns { at, of, text, asking, speaker, kind, listening }. To walk the beats, call page.evaluate(() => window.botgineer.next()) (next() advances without waiting for the typing) or click getByTestId('beat-next'). Test ids: guide (data-kind, data-speaker), speaker-name, ask-tag, beat-next, beat-back, beat-bar, ask-pointer, takeaway, replay, instrument (data-focus, class glow), actor-<id> (data-offstage, data-asleep, data-look), console-input. Call speechSettled(page) before measuring the bubble after a speaker change. window.botgineer.say(line) also skips narration.

PLACEHOLDERS to replace: meet.ts (it doubles as the engine demo; beats.spec.ts depends only on its shape — it must have several beats before an ask, a demo thought, a robot sleep/wake, a beat with focus 'console', a step praise, outro beats and a takeaway, all of which §5 already has), types.ts (it must keep teaching bool/int/float/str/kind; add 'char' only once concepts.ts has it), choose.ts, and wake.ts (editor mode: its done must match the bay's watches exactly; its awake() predicate does this).

## Stage pictures (src/scene/props.ts)

Import `type Prop` from 'src/scene/props'. Put a Prop in a Beat's or a LessonStep's `show`. What the robot answered is drawn into the current picture automatically (PropView.answer, verdict, heard). Colours are one per kind: --k-bool, --k-int, --k-float, --k-char (new), --k-str. A char is always labelled 'str · length 1', because Python has no char type.

NARRATION RULE: fields marked (narration) do not count as a different picture in sameProp. Two props that differ only in those fields are the same picture, so if F1 keeps the layer's key across such beats, the element stays and the change plays on it (the switch flips, the newcomer flies into its slot). Where an answer and a narration field disagree, the answer wins.

EXISTING (unchanged unless noted):
- { kind:'lamp', demo?:'on'|'off' }: a lamp on a switch. True lights it; a str is stuck on as a note and lights nothing. NEW demo (narration): forces the switch for a beat, 'on' flipping it to True and lighting the lamp, 'off' flipping it back. It only applies while there is no answer. Use for 1b beats 4–7 and the ask 'Turn the lamp on'.
- { kind:'fish' }: is a fish a bird? False gives ≠, True draws wings. NEW: a str answer ("no") is drawn as a note stuck on the fish, and nothing else changes (the sign still says '= ?'). For the 1c miss.
- { kind:'basket', apples:number, demo?:'count'|'half' }: answer tokens counted above the basket. NEW demo (narration): 'count' drops the apples in one at a time while a counter beside the basket rolls 1, 2, 3 in whole steps only; 'half' has half an apple land on the rim and bounce off while the counter stays and shakes. For 1b beats 9–10, e.g. {kind:'basket',apples:3,demo:'count'} then demo:'half'.
- { kind:'lift', lowest, highest, demo?:number }: the answer is the floor; a float gets stuck between floors. NEW demo (narration): sends the lift to that whole floor with no answer and highlights the floor number. For 1b beat 12: {kind:'lift',lowest:-2,highest:3,demo:-1}.
- { kind:'glass', level:number, demo?:'fill' }: normally the given glass beside a glass filled to the answer. NEW demo:'fill' (a different picture, not narration) is one larger glass filling smoothly to `level` over about 3s, with no scale marks. For 1b beat 14.
- { kind:'height' } (metres), { kind:'carton', slots } (eggs), { kind:'plate' } (breakfast bool), { kind:'match' } (hours on a line): all unchanged.
- { kind:'kinds' }: the nested rings, unchanged. The shelf replaces it in Lesson 1; practice still uses it.
- { kind:'tiles', parts?:string[], demo?:'stamp' }: a str as letter tiles, an int as a block. NEW demo:'stamp': with parts like ['"ha"','*','3'] and no answer yet, the sum sits on top and the word stamps itself down that many times (at most 6) under it, captioned '"ha", 3 times'. After a str answer it shows the result's letter tiles as before. For Level 2's "ha" * 3.
- { kind:'crates', crates, each }, { kind:'share', litres, robots }, { kind:'bolts', have, use }, { kind:'expr', text, first, then }, { kind:'phone', number }, { kind:'door' }, { kind:'card' }, { kind:'letter', char }: all unchanged.
- { kind:'balance', left, right, op:'>'|'<'|'==', lamp?:boolean }: NEW lamp (narration): a small lamp top right that lights, once the beam settles, with the truth of left op right, plus a True/False pill. Put it on the narration beat only; on the ask it would give the answer away.

NEW KINDS:
- { kind:'shelf', filled:TypeSlot[], title?, pulse?, later?, cheer?, examples?:Partial<Record<TypeSlot,string[]>> }, where TypeSlot = 'bool'|'int'|'float'|'char'|'str'. Five slots left to right. `filled` lists the named slots in the order they were named; the LAST one is the newcomer and is the only one whose label and example chips fly in. Defaults (SLOT_EXAMPLES): bool True/False; int 3, 12, -1; float 0.5, 1.4; char "A" plus the tag 'str · length 1'; str "hello", "Mira". `examples` overrides them per slot (e.g. {int:['3','12']} until the '-1' beat). An unnamed slot shows '?'. title settles 'Data types' above; pulse pulses the '?'s in turn; later adds ghost chips in [ ] tagged 'later'; cheer bounces each named slot in turn. Every thought in `heard` is filed into its own type's slot: a str of one code point goes in char, others in str. An example the player has said is drawn filled; other values are added below, newest last, at most 2 (or whatever room is left). The view's answer flies in. All fields except kind are narration. 1b: [] (beat 1) → title (2) → pulse (3) → ['bool'] (7) → ['bool','int'] (11) … → all five with cheer (29) → later (30). 1c: all five, and the answers collect.
- { kind:'numberline', from, to, mark?, unnamed? }: a track from `from` to `to` with whole numbers ticked (tenths too if the span is 2 or less). A float-coloured marker slides from `from` to `mark` while the measured stretch grows smoothly, and the value is written above it. unnamed hides the value, for the beat before '0.5' has its name. A numeric answer moves the marker instead. mark and unnamed are narration, so beat 15 {from:0,to:1,mark:0.5,unnamed:true} then beat 16 without unnamed writes the value in place.
- { kind:'letters', chars:string[] }: up to 10 char-coloured letter tiles float up into loose, tilted places. For Mira: 'I read letters.'
- { kind:'char', char:string, clasps?:boolean }: one big character tile captioned 'one character', with plain grey straight quotes either side. clasps (narration) closes the quotes over the tile's top corners as thick clasps. For beat 21.
- { kind:'contrast', left:ContrastSide, right:ContrastSide }, where ContrastSide = { text:string; kind:TypeSlot; label?:string; result?:string; resultKind?:TypeSlot }. Two cards side by side with ≠ between, each in its kind's colour, the kind word under it (char says 'str · length 1') and an optional label for people. With `result`, `text` is the expression; an arrow leads to the result card, which uses resultKind or kind. Examples: 1b beat 22 {left:{text:'7',kind:'int',label:'a number'},right:{text:'"7"',kind:'char',label:'a thing to read'}}. Level 2: {left:{text:'7 + 7',kind:'int',result:'14'},right:{text:'"7" + "7"',kind:'str',result:'"77"'}}.
- { kind:'beads', text:string, glow?:boolean }: the characters as char-coloured beads (at most 12) sliding one at a time onto a thread from the left; then a str-coloured clasp shaped like a straight quote clips on at each end, with the string written in quotes underneath. glow (narration) lights the clasps and labels them 'starts' / 'stops'. For 1b beats 25–26.
- { kind:'pointer', to:'console', label:string }: a tag with the label (wrapped, up to 3 lines of about 18 characters) and a row of chevrons running off the stage's right edge towards the console. The robot stands in front of them, and the stage clips them at its edge. For 1a beat 4, label 'your instructions go here'.
- { kind:'lamps', on:number }: 1 to 4 lit lamps, each over a True pill, joined by '+'. Each True then drops down as an int 1, and '= n' pops out, tagged int. For Level 2's True + True.
- { kind:'codes', chars:string }: each distinct character (up to 8) slides in from the left onto a number line at its code, and the code is written under its tick. Codes within 10 of each other are spaced by value, so a gap in the codes shows; wider spreads are spaced evenly in code order. For Level 2's ord, e.g. 'ABC'.
- { kind:'scale', parcels:number, each:number }: before a numeric answer, the parcels (at most 12, each labelled 'N kg') wait on the floor and the readout says '? kg'. With the answer they drop onto the platform one by one, then the readout shows '<answer> kg'. A reading that is not parcels × each turns the readout amber. For Level 5.

Pure helpers exported from src/scene/props: SLOTS, SLOT_EXAMPLES, slotOf(thought), chipText(thought), shelved(filled, heard, examples?, room?), codeLine(chars), plus numberOf/boolOf/textOf/kindOf/clamp and sameProp as before. The PropLayer interface ({view, role, beat}) is unchanged.
